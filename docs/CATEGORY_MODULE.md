# Category Module

## Overview

Categories organize products in the Seasonal Harvest catalog. Each category contains a name, optional description, optional icon, and managed timestamps.

## Database fields

| Field | Type | Rules |
|---|---|---|
| `id` | UUID | Primary key generated by PostgreSQL |
| `name` | `VARCHAR(100)` | Required, non-blank, and unique without regard to case |
| `description` | `TEXT` | Optional; maximum 1,000 characters |
| `icon` | `TEXT` | Optional; maximum 500 characters |
| `created_at` | Timestamp with time zone | Set automatically on creation |
| `updated_at` | Timestamp with time zone | Updated automatically by a database trigger |

The `icon` value may store an agreed frontend icon identifier or an icon URL. The frontend and backend team should standardize one representation before production.

## Endpoints

| Method | Endpoint | Access | Purpose |
|---|---|---|---|
| `GET` | `/api/v1/categories` | Public | List all categories |
| `GET` | `/api/v1/categories/:id` | Public | Get one category |
| `POST` | `/api/v1/categories` | Admin or super admin | Create a category |
| `PUT` | `/api/v1/categories/:id` | Admin or super admin | Update a category |
| `DELETE` | `/api/v1/categories/:id` | Admin or super admin | Delete a category |

Protected requests require:

```http
Authorization: Bearer <supabase-access-token>
```

## List categories

```http
GET /api/v1/categories?search=wet&sort=name&order=asc
```

Supported query parameters:

| Parameter | Allowed values |
|---|---|
| `search` | Partial category name |
| `sort` | `name`, `created_at`, or `updated_at` |
| `order` | `asc` or `desc` |

## Create category

```http
POST /api/v1/categories
Authorization: Bearer <supabase-access-token>
Content-Type: application/json
```

```json
{
  "name": "Wet Goods",
  "description": "Fresh meat, seafood, and other refrigerated goods.",
  "icon": "snowflake"
}
```

Only `name` is required. Unknown fields are discarded.

## Update category

```http
PUT /api/v1/categories/<category-id>
Authorization: Bearer <supabase-access-token>
Content-Type: application/json
```

```json
{
  "description": "Updated description",
  "icon": "refrigerated"
}
```

At least one of `name`, `description`, or `icon` must be supplied.

## Delete category

```http
DELETE /api/v1/categories/<category-id>
Authorization: Bearer <supabase-access-token>
```

Deletion is permanent. PostgreSQL rejects deletion when another table has a restrictive foreign-key reference to the category.

## Security

Category security is enforced twice:

1. Express verifies the Supabase access token and loads the active application profile.
2. Supabase RLS independently permits writes only when the authenticated profile is an active `admin` or `super_admin`.

Public clients receive read-only table permission. The anonymous role receives no insert, update, or delete grants.

## Migration

Apply the category schema with:

```bash
supabase db push
```

Migration file:

```text
supabase/migrations/20260728000001_create_categories_table.sql
```

The migration creates the table, validation constraints, case-insensitive unique-name index, RLS policies, secure role-check function, timestamp trigger, and least-privilege grants.
