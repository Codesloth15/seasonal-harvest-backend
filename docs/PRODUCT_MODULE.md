# Product Module

The **Product Module** is responsible for managing all products available in the Seasonal Harvest system. Products are displayed in the customer mobile application, managed by administrators through the web application, and referenced by inventory and orders.

Each product belongs to a **category** and may optionally belong to a **brand**.

---

# Purpose

The Product Module allows administrators to:

- Create new products
- View all products
- View a specific product
- Update product information
- Enable or disable products
- Organize products by category and brand

Products are one of the core entities of the system and are used by customers when placing orders.

---

# Database Structure

Table: `products`

| Column | Type | Description |
|----------|------|-------------|
| id | UUID | Primary Key |
| category_id | UUID | References categories.id |
| brand_id | UUID | References brands.id (nullable for unbranded products) |
| name | TEXT | Product name |
| description | TEXT | Product description |
| product_type | TEXT | BRANDED or UNBRANDED |
| sku | TEXT | Stock Keeping Unit (Unique) |
| barcode | TEXT | Barcode |
| unit | TEXT | Unit of measurement |
| price | DECIMAL | Product selling price, stored in Philippine pesos |
| currency | TEXT | Response-only currency code: `PHP` |
| image_url | TEXT | Product image |
| is_active | BOOLEAN | Product availability |
| created_at | TIMESTAMP | Creation date |
| updated_at | TIMESTAMP | Last updated |

# Get All Products

Returns all available products.

### Request

```
GET /api/v1/products
```

Optional Query Parameters

| Parameter | Description |
|------------|-------------|
| categoryId | Filter by category |
| brandId | Filter by brand |
| productType | BRANDED or UNBRANDED |
| search | Search product name |
| active | true / false |
| sort | Sort column |
| order | asc / desc |

Example

```
GET /api/v1/products?categoryId=123
```

Example

```
GET /api/v1/products?brandId=456
```

Example

```
GET /api/v1/products?search=hotdog
```

# Create Product

Creates a new product.

### Request

```
POST /api/v1/products
```

### Multipart body

```javascript
const body = new FormData();
body.append("category_id", "08bba764-9cd8-49b1-ac26-dd4f3aac5f95");
body.append("brand_id", "de63c12b-dede-4856-8599-26094c6e1073");
body.append("name", "Tender Juicy Hotdog Regular 1kg");
body.append("description", "CDO Tender Juicy Regular Hotdog");
body.append("product_type", "BRANDED");
body.append("barcode", "4801234567890");
body.append("unit", "pack");
body.append("price", "185");
body.append("image", imageFile);
```

> SKU is automatically generated by the backend.

The `image` field accepts one JPEG, PNG, WebP, or AVIF file up to 5 MB. The
route requires an active admin or super-admin. The backend stores the object
under `product-images/{product-id}/{generated-filename}` and saves its public
URL in `products.image_url`.

### Known Base64 failure

Do not convert the file to Base64 and place it in a JSON `image_url` field.
That representation expands the request and can exceed the backend's 100 KB
JSON body limit, producing `413 Payload Too Large`. A CORS warning shown beside
the 413 is secondary; the oversized JSON request is the primary failure. Send
the original `File` with `multipart/form-data`. In a browser, do not manually
set `Content-Type` because the browser must add the multipart boundary.

`price` is sent as a number in Philippine pesos. Product responses include
`"currency": "PHP"`; format the amount as `₱185.00` in the client.

Example generated SKU

```
CDO-HOTDOG-001
```

# Update Product

Updates an existing product.

### Request

```
PUT /api/v1/products/:id
```

Example Body

```json
{
    "price": 195,
    "image_url": "https://example.com/new-image.jpg",
    "is_active": true
}
```

# Delete Product

### Request


Current implementation:

- Permanently remove the product row

# Notes

- SKU must be unique.
- Barcode is optional.
- Product image support is partial until the Supabase storage-policy migration is applied and the frontend multipart flow is verified.
- `image_url` stores the public URL returned for an object in the Supabase `product-images` bucket; it must not contain Base64 image data.
- Products are filtered using `is_active`.
- Customers should only retrieve active products.
- Admins manage all product operations.
