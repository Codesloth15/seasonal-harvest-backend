# Product Module

The **Product Module** is responsible for managing all products available in the Seasonal Harvest system. Products are displayed in the customer mobile application, managed by administrators through the web application, and referenced by inventory and orders.

Each product belongs to a **category** and may optionally belong to a **brand**.

---

# Purpose

The Product Module allows administrators to:

- Create new products
- View all products
- View a specific product
- Update product information
- Enable or disable products
- Organize products by category and brand

Products are one of the core entities of the system and are used by customers when placing orders.

---

# Database Structure

Table: `products`

| Column | Type | Description |
|----------|------|-------------|
| id | UUID | Primary Key |
| category_id | UUID | References categories.id |
| brand_id | UUID | References brands.id (nullable for unbranded products) |
| name | TEXT | Product name |
| description | TEXT | Product description |
| product_type | TEXT | BRANDED or UNBRANDED |
| sku | TEXT | Stock Keeping Unit (Unique) |
| barcode | TEXT | Barcode |
| unit | TEXT | Unit of measurement |
| price | DECIMAL | Product selling price |
| image_url | TEXT | Product image |
| is_active | BOOLEAN | Product availability |
| created_at | TIMESTAMP | Creation date |
| updated_at | TIMESTAMP | Last updated |

# Get All Products

Returns all available products.

### Request

```
GET /api/v1/products
```

Optional Query Parameters

| Parameter | Description |
|------------|-------------|
| categoryId | Filter by category |
| brandId | Filter by brand |
| productType | BRANDED or UNBRANDED |
| search | Search product name |
| active | true / false |
| sort | Sort column |
| order | asc / desc |

Example

```
GET /api/v1/products?categoryId=123
```

Example

```
GET /api/v1/products?brandId=456
```

Example

```
GET /api/v1/products?search=hotdog
```

---

# Get Product By ID

Returns one product.

### Request

```
GET /api/v1/products/:id
```

Example

```
GET /api/v1/products/67f7d4...
```

---

# Create Product

Creates a new product.

### Request

```
POST /api/v1/products
```

### Body

```json
{
    "category_id": "08bba764-9cd8-49b1-ac26-dd4f3aac5f95",
    "brand_id": "de63c12b-dede-4856-8599-26094c6e1073",
    "name": "Tender Juicy Hotdog Regular 1kg",
    "description": "CDO Tender Juicy Regular Hotdog",
    "product_type": "BRANDED",
    "barcode": "4801234567890",
    "unit": "pack",
    "price": 185,
    "image_url": "https://example.com/hotdog.jpg",
    "is_active": true
}
```

> SKU is automatically generated by the backend.

Example generated SKU

```
CDO-HOTDOG-001
```

---

# Update Product

Updates an existing product.

### Request

```
PUT /api/v1/products/:id
```

Example Body

```json
{
    "price": 195,
    "image_url": "https://example.com/new-image.jpg",
    "is_active": true
}
```

---

# Delete Product

Deletes or disables a product.

### Request

```
DELETE /api/v1/products/:id
```

Recommended implementation:

- Soft delete
- Set `is_active = false`

# SKU Generation

Every branded product automatically receives a unique SKU.

Example

```
Brand

CDO

Product

Tender Juicy Hotdog

↓

Generated SKU

CDO-HOTDOG-001
```

The backend checks existing SKUs before assigning the next sequence number.

# Product Types

### BRANDED

Products manufactured by a company.

Examples

- CDO Tender Juicy
- Purefoods Hotdog
- Virginia Longganisa

Requires a `brand_id`.

---

### UNBRANDED

Products without a manufacturer.

Examples

- Tomatoes
- Onion
- Potato
- Cabbage

`brand_id` may be null.

# Notes

- SKU must be unique.
- Barcode is optional.
- Image URL stores the Firebase Storage image.
- Products are filtered using `is_active`.
- Customers should only retrieve active products.
- Admins manage all product operations.
